# O AI — build plan and requirements sheet

Date: 2026-11-04. Repo: `O`. Product name: **O AI** (short: **O**).

## What it is

A desktop agent in the exact shape of [opia](https://github.com/samuelsortland-cmyk/opia) (pixel pet, chat panel,
non-focus-stealing cards, Claude Code CLI as the brain, O Link for the user's own browser tabs) with a new
**Python provisioning engine** underneath and one **action log** that records everything either side does.

Goals, verbatim from the user: *most accurate, least disruptive, least slow, least inefficient*. Security and
user safety come from **recording every action in a text log and informing the user when they click the log**.

## Global constraints (apply to every parcel)

- Brain: Claude Code CLI (`claude -p`) with the user's own login. No API key anywhere.
- Default permission mode is **`log`**: nothing asks; everything is recorded. `ask` (blocking card, 60 s timeout
  destroys the queue) and `auto` (no gating, no cards) remain selectable. Payment blocking in O Link stays.
- Hard requirements (documented, installed by `install/` scripts, checked at startup, surfaced in Settings as
  green/red): Node 18+, Claude Code CLI, Python 3.10+, vLLM (local OpenAI-compatible server at
  `http://127.0.0.1:8000/v1`), screenpipe (local SQLite at the default path), Playwright + Chromium, Xvfb on Linux
  (display `:99`). On macOS/Windows the isolated display is headless-only; say so, do not fake it.
- Nothing ever drives the host mouse, keyboard, or primary display. Browser work goes through O Link (CDP into
  the page) or headless Playwright. Engine commands run in a sandbox directory tree.
- Every action is logged: tool calls, their result status, engine graph transitions, cache hits, remediation
  attempts, approvals, settings changes. The log is append-only and hash-chained.
- Node code: CommonJS, `'use strict'`, no new runtime dependencies beyond `ws` and `@playwright/mcp`.
  Python: pydantic v2, langgraph, fastapi, uvicorn, httpx, openai, playwright, pillow (zoom-in grounding crops). Tests with pytest.
- Prose and code stay separate: no explanatory prose inside code blocks beyond normal comments.
- Keep opia's visual design. Rebrand is done (`Opia`→`O`, `window.opia`→`window.o`, `mcp__opia__`→`mcp__o__`).

## Shared contracts (Wave 0 — fixed; build against these)

### Action log entry (both sides)

```json
{
  "ts": 1730000000.123,
  "iso": "2026-11-04T22:30:00",
  "source": "app" | "engine",
  "kind": "task" | "tool" | "result" | "policy" | "graph" | "cache" | "remediate" | "verify" | "settings" | "note",
  "summary": "one human line",
  "detail": { },
  "prev": "<sha256 of previous entry>",
  "hash": "<sha256 of this entry without hash>"
}
```

App file: `<userData>/o-actions.jsonl` (+ `o-actions.log` text twin). Engine file: `<dataDir>/engine-actions.jsonl`
(+ `.log`). Engine also POSTs each entry to the app at `O_LOG_URL` with header `x-o-token`.

### App ⇄ engine HTTP (engine = FastAPI on 127.0.0.1, port chosen by the app; header `x-o-token` required)

| Method | Path | Body | Returns |
|---|---|---|---|
| GET | `/health` | — | `{ok, version, vllm: bool, screenpipe: bool, xvfb: bool, playwright: bool}` |
| POST | `/provision` | `ProvisionRequest` JSON | `{job_id}` |
| GET | `/jobs/{id}` | — | `JobState` (see below) |
| POST | `/jobs/{id}/approve` | `{allow: bool}` | `{ok}` (only in ask mode) |
| POST | `/cache/lookup` | `{request: ProvisionRequest}` | `{hit: bool, fingerprint, script_path?}` |
| GET | `/cache` | — | `[{fingerprint, label, created, platform, runs}]` |
| POST | `/diagnose` | `{stderr, stdout, exit_code, command, cwd}` | `Diagnostic` JSON |
| POST | `/parse` | `{text}` (an error or a goal) | `{steps: [...]}` or 422 with `SchemaViolation` text |
| POST | `/verify` | `VerifyTarget` | `{ok, status, elapsed_ms, error?}` |
| GET | `/context` | `?cwd=` | `WorkspaceProfile` JSON |

`JobState`: `{id, label, phase, attempt, max_attempts, cached: bool, steps: [{index, command, cwd, exit_code,
stdout_tail, stderr_tail, elapsed_ms}], diagnostic?, verify?, done: bool, ok: bool, error?}`.
`phase` ∈ `context | validate | cache_lookup | gate | execute | verify | remediate | cache_store | report`.

### Engine graph (fixed topology, compiled once)

```
context -> validate -> cache_lookup -> gate -> execute -> verify -> cache_store -> report
                                        ^                  |  (fail)
                                        |                  v
                                        +--- remediate <---+     (attempt < max_attempts, default 3; else report)
```

Edges are literal in `graph.py`; no node may add or change edges. Remediation is the only cycle and is bounded.

### MCP tools exposed to Claude Code (server name `o`, so tool ids are `mcp__o__<name>`)

| Tool | Input | Purpose |
|---|---|---|
| `approve` | `{tool_name, input, tool_use_id}` | Claude Code permission prompt tool (log mode: always allow + log) |
| `see_screen` | `{display?}` | screenshot of display under cursor (existing) |
| `log_note` | `{text}` | agent writes a one-line explanation into the action log |
| `provision` | `ProvisionRequest` | run the engine graph; returns final `JobState` (blocks until done) |
| `cache_lookup` | `{request}` | is there a cached script for this request |
| `diagnose` | `{stderr, stdout, exit_code, command, cwd}` | structured diagnostic (vLLM + telemetry) |
| `verify_port` | `VerifyTarget` | headless Playwright check |
| `workspace_context` | `{cwd?}` | ambient profile: shell history tail, tree, config files, recent telemetry |

### Pydantic schema (done: `engine/o_engine/schema.py`)

`ProvisionStep{target_directory:str, command_string:str, timeout_seconds:int}` frozen, extra=forbid, strict.
`VerifyTarget{port, path='/', expect_status=200, timeout_seconds=30}`.
`ProvisionRequest{label, steps: tuple[ProvisionStep,...], verify?: VerifyTarget, isolated_display=False}`
with `.fingerprint(platform)`. `parse_request(raw)`, `parse_steps(raw, label)` raise `SchemaViolation`.

### Settings additions (`main/settings.js`)

`permissionMode: 'log' | 'ask' | 'auto'` (default `'log'`), `enginePython: ''` (auto), `vllmUrl:
'http://127.0.0.1:8000/v1'`, `vllmModel: 'meta-llama/Meta-Llama-3-8B-Instruct'`, `screenpipeDb: ''` (auto),
`sandboxRoot: <home>/o-sandbox`, `maxRemediationAttempts: 3`, `logUnreadBadge: true`.

## Categories and requirement blocks

### A. engine (Python, `engine/`)

- A1 `context.py` — ambient context: SQLite `context.db` with tables `shell_history(ts, shell, cwd, cmd)`,
  `tree_snapshots(ts, root, json)`, `config_files(ts, path, sha256, head)`; a `collect(cwd)` that reads
  `~/.bash_history`, `~/.zsh_history`, PowerShell `ConsoleHost_history.txt` (tail 200), walks `cwd` 3 levels
  (ignoring node_modules/.git/venv), hashes known config files (package.json, pyproject.toml, requirements.txt,
  docker-compose.yml, .env.example, Makefile); `profile(cwd) -> WorkspaceProfile` (pydantic) merging the DB with
  screenpipe's last 120 s of OCR text + window titles (`ScreenpipeTelemetry(db_path).recent(seconds)`), with a
  local JSONL fallback when screenpipe's DB is absent. Zero questions asked of the user.
- A2 `tokenfilter.py` + `parser.py` — `TokenFilter` consumes a token stream (iterator of str) and yields only
  bytes inside the first balanced JSON array/object; everything before `[`/`{` and after the close is dropped;
  fences and prose never reach the parser. `LocalModelParser(vllm_url, model)` streams
  `chat.completions` with `stream=True`, pipes through `TokenFilter`, then `parse_steps`. `ClaudeCodeParser`
  runs `claude -p --output-format json` with the same prompt as fallback. `Parser.parse(text, goal) ->
  ProvisionRequest` tries local first, falls back once, raises `SchemaViolation` otherwise.
- A3 `executor.py` + `display.py` + `cache.py` — `Sandbox(root)`: `resolve(target_directory)` must stay
  inside root (symlinks resolved) else `SandboxEscape`; `run(step, env) -> StepResult{exit_code, stdout,
  stderr, elapsed_ms, timed_out}` via `subprocess.run` with `timeout`, `stdin=DEVNULL`, scrubbed env (no
  CLAUDE*, no tokens), `DISPLAY=:99` when isolated. `IsolatedDisplay(':99')` starts `Xvfb :99 -screen 0
  1280x800x24` if `Xvfb` exists (Linux), `.available` false elsewhere. `ScriptCache(dir)`: `lookup(fp)`,
  `store(fp, request, script_text, platform)` writes `<fp>.sh|.ps1` + `<fp>.json` with `O_NOCLOBBER` (never
  overwrite; never delete), `replay(fp, sandbox) -> StepResult`, `index()`.
- A4 `graph.py` + `gate.py` + `remediate.py` — langgraph `StateGraph` with exactly the nodes/edges in Shared
  contracts; `EngineState` TypedDict; `build_graph(deps)` compiles once at import of server; `Gate(mode,
  approve_waiter)`: `log` → record+pass, `auto` → pass, `ask` → wait ≤60 s for `/jobs/{id}/approve`, timeout or
  deny raises `QueueDestroyed` which empties the job queue. `Remediator`: reads stderr line-by-line, uses
  `Parser.parse(stderr, goal=original label)` to get replacement steps, applies **surgical** file edits only
  through `Sandbox` (a `patch` dict `{path, find, replace}` validated by pydantic), re-queues execute.
  Attempt counter is in state; `max_attempts` from request/env; exceeding → report with `ok=false`.
- A5 `server.py` + `cli.py` — FastAPI app per the HTTP table, token from `O_ENGINE_TOKEN`, port from
  `--port`, data dir from `--data-dir`; jobs run in a `ThreadPoolExecutor(max_workers=4)` (parallel jobs,
  each its own sandbox subdir). `/health` probes vLLM (`GET /models`), screenpipe DB file, `Xvfb` on PATH,
  Playwright chromium. `o-engine serve|run <file.json>|cache ls|context [cwd]|check`. Every state change
  goes to `ActionLog.record`.
- A-tests: `tests/test_schema.py` (fences, prose, extra keys rejected; valid passes; fingerprint stable),
  `test_tokenfilter.py`, `test_sandbox.py` (escape rejected, timeout honored), `test_cache.py` (noclobber,
  replay), `test_graph.py` (happy path hits cache on second run and skips parser; failure loops ≤ max then
  reports), `test_server.py` (FastAPI TestClient, token required). Use stubs for vLLM/screenpipe.

Ruled out: asking the user anything from the engine; mutating graph edges at runtime; deleting cache
entries; running outside the sandbox root; touching the host display.

## Failure modes the specs imply but no task's tests exercise (must be covered)

- Engine crash mid-job → app marks job failed, logs it, restarts engine, queue continues.
- vLLM down → parser falls back to Claude Code; health shows red; nothing hangs > 10 s.
- screenpipe absent → context still builds from history + tree; health shows red.
- Cache entry whose script now fails → treated as a failure (remediate), never deleted.
- Log file tampered → `Verify chain` reports the first broken index.
- Two jobs at once → separate sandbox subdirs, interleaved log entries still chain correctly (single writer lock).

## E. API proxy (spec 3: "Subprocess Session Wrapper & Token Normalization Proxy") — added 2026-11-04 22:42

Goal: a localhost, OpenAI-compatible HTTP proxy in the Electron main process that turns API requests into
`claude -p` subprocess runs (the user's own login), normalizes the stream back into standard JSON / SSE,
strips conversational padding, and records every request in the action log.

Decisions (builder's, stated): the spec's `CLAUDE_DANGEROUSLY_SKIP_PERMISSIONS` is NOT used — O's `log`
mode already makes every tool call un-gated, but through the bridge, so each call is still a logged policy
entry; skipping permissions at the CLI would remove those entries. The spec's "prompt interception" strips
O's own pet persona, prose styling and reply-length rules for API callers and injects a code-only template;
it never strips safety rules (payments, credentials, untrusted content).

- E1 `main/promptmod.js` — `buildSystemPrompt({mode:'code'|'chat', extra})`: `code` = the CODE_ONLY
  template (answer with code or structured JSON only; no preamble, no explanation unless asked; keep the
  Money / untrusted-content / no-credentials rules verbatim from agent.js PERSONA_TEMPLATE); `chat` = the O
  persona. `stripPersona(text)` applies an ordered list of regex rules (`RULES`, exported, each `{name,
  pattern, replace}`) that remove persona/style lines (hat, monocle, "warm, a bit theatrical", reply-length
  rules) so a caller-supplied `system` message can be merged without duplicated narrative.
- E2 `main/proxy.js` — `createProxy({getSettings, actionLog, getEngine, spawn?})` → `{start(), stop(),
  status()}`. Listens on `127.0.0.1:<settings.proxyPort>` (default 8787) only; every request must carry
  `Authorization: Bearer <settings.proxyToken>` (generated once, shown in Settings). Routes:
  `GET /health`; `GET /v1/models` → `[{id:'o-ai'}, {id:'o-ai-code'}]`; `POST /v1/chat/completions` (OpenAI
  shape: model, messages, stream, tools?, response_format?) → spawns `claude -p --output-format stream-json
  --verbose --max-turns N --permission-prompt-tool mcp__o__approve --mcp-config <same file agent.js
  writes> --allowedTools ...` with the system prompt from promptmod (`--system-prompt-file` when the CLI
  supports it — detect once via `claude --help`; else `--append-system-prompt-file`), the conversation
  flattened to one prompt on stdin; stream-json assistant text deltas → OpenAI `chat.completion.chunk`
  SSE frames (`data: {...}\n\n`, final `data: [DONE]`), tool_use blocks → `tool_calls` entries, `result`
  → `finish_reason` + `usage` (cost/duration in `x-o-cost-usd`/`x-o-duration-ms` headers for non-stream);
  when `response_format.type === 'json_object'` or model `o-ai-code`, the text passes through a TokenFilter
  port (`main/tokenfilter.js`, same semantics as engine/o_engine/tokenfilter.py: only the first balanced
  JSON value; fences and prose dropped) before being returned. `POST /v1/run` (O-native): `{objective,
  cwd?}` → engine `/context` (state recovery) → cache lookup by objective fingerprint → if hit, replay via
  engine `/provision` with the cached request; else one `claude -p` call in code mode asking for strict
  steps, parsed by the TokenFilter, posted to engine `/provision`; returns the JobState. Concurrency: up to
  `settings.proxyConcurrency` (default 4) child processes; a queue beyond that; each run has its own
  sessionless `claude` process (no --resume). Every request → action log `{kind:'task', summary:'API:
  <route> <model> <clip of last user message>'}` and `{kind:'result', ...}` on completion; never log the
  bearer token.
- E3 `main/tokenfilter.js` + `main/tools/selftest-proxy.js` — node port of TokenFilter; selftest spawns
  the proxy with `spawn` injected to run `main/tools/fake-claude.js` and asserts: 401 without token;
  /v1/models; non-stream completion returns OpenAI JSON with the fake's text; stream returns ≥2 SSE chunks
  and `[DONE]`; `o-ai-code` model with prose+JSON fake output returns only the JSON; concurrency cap
  honored (5 parallel requests, max 4 children at once); action log received task+result entries.
- E4 wiring (owner: whoever owns main.js/settings.js/preload at the time): settings `proxyEnabled: true`,
  `proxyPort: 8787`, `proxyToken: ''` (generated on first run, persisted), `proxyConcurrency: 4`,
  `proxyMode: 'code'`; main.js starts/stops the proxy with the app and on settings change; preload
  `proxyStatus()`; renderer Settings → "API proxy" section showing URL, token (masked, copy button), on/off.
- E5 docs: README "API proxy" section with a curl example and the OpenAI-SDK `base_url` example;
  ARCHITECTURE.md section 8 "API proxy" incl. the two decisions above; engine/README unchanged.

Ruled out: exposing the proxy on non-loopback interfaces; running without a bearer token; stripping safety
rules; `--dangerously-skip-permissions`.

## F. Computer use — target: surpass Simular (Agent S3/S4, SimuLang) — added 2026-11-04 22:44

What Simular does (Nov 2026, from their own pages): accessibility-tree-first element targeting with vision
fallback; solved tasks compiled to deterministic replay scripts (no tokens on replay); judge models check the
screen before a step is marked done; self-healing scripts; Behavior Best-of-N (run N agents, pick the best);
Agent S4 evolves per-app "interfaces + usage knowledge" from trajectories. Agent S3 reports 72.6% OSWorld.

Builder's framing (stated plainly): no benchmark number is claimed by this build. The parcel delivers the
capability plus an OSWorld-Verified runner; the number is measured by running it. Axes O must beat them on
and can prove in-repo: (1) zero host disruption — API-level actions (AT-SPI / UIA / AX invoke & set-value)
that never move the mouse, pixel actions only inside the isolated display; (2) every step logged with its
pre/post evidence in the action log; (3) replay without inference plus bounded self-heal, append-only
lineage; (4) judged steps (accessibility assertion first, VLM judge second); (5) parallel best-of-N across
separate Xvfb displays; (6) per-app interface notes that grow from trajectories.

### Contracts

OScript (JSON, strict pydantic, frozen, extra=forbid):
```
{ "app": "libreoffice-calc", "goal": "…", "steps": [
  {"op":"launch","cmd":"libreoffice --calc"},
  {"op":"wait","for":{"role":"frame","name":"*Calc*"},"timeout_s":20},
  {"op":"find","as":"cell","target":{"role":"table cell","name":"A1"}},
  {"op":"click","ref":"cell"} | {"op":"type","ref":"cell","text":"42"} | {"op":"key","keys":"ctrl+s"} |
  {"op":"set_value","ref":"x","value":"…"} | {"op":"invoke","ref":"x","action":"press"} |
  {"op":"assert","target":{"role":"…","name":"…","state":"focused|checked|visible"}} |
  {"op":"screenshot_assert","question":"Is the file saved?"} ] }
```
`target` fields: role, name (glob), text, index, within (ref). Resolution order: accessibility backend →
cached locator → vision grounding (screenshot + local VLM → bbox; Claude Code fallback) → fail.

Backends (`o_engine/cu/backends/`): `atspi.py` (Linux, pyatspi via gi; DISPLAY from IsolatedDisplay),
`uia.py` (Windows, `uiautomation` package), `ax.py` (macOS, `atomacos`/pyobjc). Each implements
`CUBackend`: `tree(window=None) -> list[Node{id, role, name, text, rect, states, children}]`,
`find(target) -> Node|None`, `click(node)`, `invoke(node, action)`, `set_value(node, value)`,
`type_text(node, text)`, `key(keys)`, `screenshot() -> png bytes`, `focused_window()`. API-level first;
`click` falls back to coordinates only when `allow_pixels` (true only on the isolated display).
Import failures make a backend `available=False`; `/health` reports `cu_backend`.

Grounding (`o_engine/cu/ground.py`): `VisionGrounder(vllm_url, model)` sends screenshot + target text to a
local VLM (OpenAI vision format; default model setting `vllmVisionModel`, e.g. a UI-grounding VLM), parses
`{x,y,w,h}` through TokenFilter; `ClaudeCodeGrounder` fallback via `claude -p` with the image path;
results cached per (app, target, screen hash) in `locators.sqlite`.

Judge (`o_engine/cu/judge.py`): after each step, `assert`-type checks run on the accessibility tree; if the
step declares `expect`, a `screenshot_assert` is answered by the VLM judge (yes/no + reason). A step is
"done" only when its judge passes; otherwise the heal loop runs.

Planner + best-of-N (`o_engine/cu/planner.py`): `plan(goal, app, interface_notes, tree_summary) ->
OScript` via Parser (local model → Claude Code); `BestOfN(n)` plans N candidates, runs each in its own
isolated display (`:99 + i`), scores with the judge (goal-level `screenshot_assert` + step pass ratio +
fewest steps), keeps the winner. `n` from setting `cuCandidates` (default 1; 3 recommended on Linux).

Procedures (`o_engine/cu/procedures.py`): append-only store `procedures/<app>/<goal-hash>/v<N>.json`
with lineage (`parent`, `healed_step`, `reason`); replay = run the script with no model calls; on a judged
failure the heal loop asks the planner for a replacement for that one step, writes v<N+1>, continues
(max `cuMaxHeals`, default 3). Nothing is ever deleted.

Interface notes (`o_engine/cu/interfaces.py`): per-app markdown `interfaces/<app>.md` (what worked, what
the tree looks like, pitfalls) appended by a bounded summarizer after each run (local model, ≤40 lines per
run, file capped at 400 lines by keeping the newest sections); read into every plan prompt. This is the
Agent S4 idea kept append-only and inspectable.

Engine routes: `POST /computer/run {goal, app?, candidates?, display?} -> {job_id}` (same job model and
JobState, phases context|plan|ground|execute|judge|heal|store|report); `GET /computer/procedures`;
`POST /computer/replay {procedure_id}`; `GET /computer/tree?window=`; `POST /computer/find {target}`.

## H. Phase 3 — declarative streaming GenUI (A2UI / sandboxed render / token-compressed layouts) — added 2026-11-04 23:11

Builder's decisions (stated): the agent (Claude Code child) and the engine emit UI only as validated
declarative frames; raw HTML/markdown from the model is never rendered in the panel. The renderer maps
frames onto O's own design tokens and native DOM. Custom previews (HTML/CSS/JS the engine or a
validation step produced, e.g. a page snapshot from verify) render only inside a sandboxed iframe
(`sandbox="allow-scripts"`, no `allow-same-origin`, strict CSP via srcdoc, postMessage only). The
compressed form is O's own compact grammar ("oui"), documented and validated on both sides.

### Contracts
A2UI-style JSONL frames (pydantic strict on the engine, hand-written validator in the renderer):
```
{"a2ui":"1","type":"begin","surface":"job:<id>","title":"…"}
{"a2ui":"1","type":"update","surface":"job:<id>","components":[{"id":"plan","component":{"Column":{"children":["s0","s1"]}}},
  {"id":"s0","component":{"Step":{"label":"npm install","status":"running|ok|failed|pending|skipped","detail":"…","progress":0.4}}},
  {"id":"t","component":{"Text":{"text":"…","tone":"muted|normal|error"}}},
  {"id":"tree","component":{"Tree":{"nodes":[{"id","label","status","children":[…]}]}}},
  {"id":"c","component":{"Card":{"title":"…","children":[…]}}}, {"id":"b","component":{"Button":{"label":"…","action":"open-log|open-file|retry|approve|deny","payload":{}}}},
  {"id":"k","component":{"KeyValue":{"items":[["k","v"]]}}}, {"id":"p","component":{"Preview":{"sandbox_id":"…","height":240}}}]}
{"a2ui":"1","type":"data","surface":"…","path":"steps.0.status","value":"ok"}
{"a2ui":"1","type":"end","surface":"…","ok":true}
```
Component set is closed: Column, Row, Card, Text, Step, Tree, Progress, KeyValue, Button, Preview. Unknown
component or property → frame rejected and logged (kind 'note'), never rendered. Button actions are a
closed enum handled by the panel (open-log, open-file, retry, approve, deny).

Sandboxed render: `{"a2ui":"1","type":"sandbox","surface":"…","sandbox_id":"…","html":"…","css":"…","js":"…"}`
→ renderer builds a srcdoc with `<meta http-equiv="Content-Security-Policy" content="default-src 'none';
style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:">`, `sandbox="allow-scripts"`, fixed
height, and a postMessage bridge that accepts only `{type:'o-ui-event', name, payload}` from that frame's
window; nothing from the iframe reaches the main process except through that bridge, and every event is
logged.

Token-compressed form "oui" (both sides): one line per component, `<Type>#<id>[<k>=<v>;…]{<child ids>}`,
values JSON-encoded only when needed, e.g. `Step#s0[l="npm install";st=run;p=0.4]`, `Col#plan{s0 s1}`.
`compile(frames) -> str` on the engine, `decode(text) -> frames` in the renderer with the same validator;
the engine sends oui over the wire (`GET /jobs/{id}/ui?format=oui|a2ui`) and the bridge tool accepts
either. A round-trip test proves `decode(compile(x)) == x`.

Engine emitters: every job (provision, cu, swarm, web) owns a surface `job:<id>`; the graph's tracker
emits `begin` at context, a `Tree`/`Step` update per node transition, `data` patches for step status, and
`end` at report; verify/judge nodes may attach a `Preview` sandbox (e.g. the page title + status text of a
verified port, rendered as a tiny HTML card). Frames are stored per job (ring buffer 2000) and streamed
over `GET /jobs/{id}/ui` as SSE; the app relays them to the panel as `{type:'genui', frame}`.

Agent side: bridge tool `ui_emit {frames: [...]}` (strict schema) for Claude Code to push A2UI frames into
the current chat's surface `chat:<session>`; persona line: "when you report plans, progress or results,
prefer mcp__o__ui_emit frames over prose; the panel renders them". The panel shows GenUI surfaces inline
in the chat (a `Surface` card per surface id) and in a new "Runs" sheet listing active/past job surfaces.

Settings: `genuiEnabled` (true), `genuiSandbox` (true). Env: O_GENUI.

### Parcels
- H1 engine: `o_engine/genui.py` (pydantic frame models, closed component set, `UIStore` ring buffer per
  surface, emitters, `oui.compile/decode`), graph tracker hooks (provision + cu graphs via the existing
  tracker/progress seams, no edge changes), routes `GET /jobs/{id}/ui` (SSE, `?format=`), `POST
  /ui/emit` (for the bridge), tests (schema rejects unknown components; oui round trip; a provision job
  produces begin → updates → end; SSE route streams).
- H2 renderer: `renderer/genui.js` (validator, oui decoder, A2UI → DOM using panel.css tokens, Step/Tree
  components with status pills reusing the action-log pill styles, sandboxed Preview iframe with CSP +
  postMessage bridge, closed Button actions), panel integration (surface cards in chat, "Runs" sheet),
  `renderer/genui.css`, CSP update in panel.html if needed (iframes with srcdoc; `frame-src` allow
  `about:` / data), Playwright screenshot check.
- H3 app: main.js relays engine SSE per active job → `{type:'genui', frame}`; preload `onGenui(cb)`,
  `genuiFrames(surface)`; bridge tool `ui_emit`; agent persona line; settings keys; action-log entries for
  every sandbox event; tests (node selftest for the relay + bridge).
- H4 docs: README "Generative UI" + ARCHITECTURE §11 (why declarative, the sandbox model, oui grammar).

Ruled out: rendering model-produced HTML/markdown outside the sandbox; `allow-same-origin`; any
component or action outside the closed sets; UI frames that skip the action log.
